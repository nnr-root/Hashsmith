# MD4/NTLM Fast Path Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the pipelined NEON vector fast path from MD5 to MD4 and NTLM, so unsalted fixed-length brute/mask attacks against those types get the same ~5.6x speedup MD5 now has.

**Architecture:** Three pieces, in order. First generalise what already exists — `transposedBatch` gains a candidate *encoding* mode (NTLM is `MD4(UTF-16LE(password))`, so its message bytes are not its candidate bytes), and the single-algorithm fast-path seam becomes a small algorithm descriptor so we do not end up with three near-identical concurrent runners. Second, the MD4 core itself, generated the same way the MD5 one was. Third, wiring and measurement.

**Tech Stack:** Go 1.25+, arm64 NEON assembly in Plan 9 syntax generated by a committed Python generator, `golang.org/x/crypto/md4` as the scalar reference. No cgo.

**Spec:** `docs/superpowers/specs/2026-08-31-hashsmith-throughput-and-reach-design.md` §5.4 priority 2 ("MD4 / NTLM — same lack of hardware support, and NTLM dominates Active Directory work"). Read that spec's ERRATUM box first: several of its Phase 1 claims were disproven, and the measured outcome lives in `docs/superpowers/notes/2026-08-31-phase1-measurements.md`.

**Prior art in-repo — read these before starting, they are the template:**
- `hashsmith/go_hashsmith/cmd/hashsmith/transposed.go` — candidate generation in vector layout
- `hashsmith/go_hashsmith/cmd/hashsmith/md5neon_gen.py` — the generator, including its register-budget commentary
- `hashsmith/go_hashsmith/cmd/hashsmith/md5neon_arm64.go` / `md5neon_generic.go` — the wrapper and the fallback-as-oracle

## The one thing most likely to go wrong

**NTLM is `MD4(UTF-16LE(password))`, and Hashsmith's UTF-16LE is not naive byte expansion.**

`utf16le` (`hash.go:468`) is `utf16.Encode([]rune(s))` — a UTF-8 *decode* followed by a UTF-16 encode. For ASCII input that is identical to emitting `b, 0x00` per byte. For a non-ASCII byte it is not: `[]rune(string([]byte{0xC3}))` yields U+FFFD, so the scalar path emits `0xFD 0xFF`, not `0xC3 0x00`.

Hashsmith masks can produce non-ASCII bytes — `?b` is a full-byte charset. So a fast path that expands naively would compute **different digests than Hashsmith's own scalar path** for those candidates, silently. Task 3 handles this by restricting NTLM eligibility to all-ASCII charsets, and pins it with a test. Do not skip that.

MD4 proper takes raw candidate bytes and has no such issue.

**MD4 versus MD5 — the algorithm differences that matter to the generator:**

| | MD5 | MD4 |
|---|---|---|
| rounds | 64 (4 passes) | **48** (3 passes) |
| step | `a = b + rotl(a + F + K[i] + M[g], s)` | **`a = rotl(a + F + K + M[g], s)`** — no `+ b` |
| constants | 64-entry table | **per-pass**: 0, `0x5A827999`, `0x6ED9EBA1` |
| round 1 | `F = (b&c)\|(~b&d)` | `F = (b&c)\|(~b&d)` (same) |
| round 2 | `G = (d&b)\|(~d&c)` | **`G = (b&c)\|(b&d)\|(c&d)`** (majority) |
| round 3 | `H = b^c^d` | `H = b^c^d` (same) |
| round 4 | `I = c^(b\|~d)` | **none** |

Shift tables: pass 1 `3,7,11,19`; pass 2 `3,5,9,13`; pass 3 `3,9,11,15` (each repeating per group of 4).
Message order: pass 1 `0..15`; pass 2 `0,4,8,12,1,5,9,13,2,6,10,14,3,7,11,15`; pass 3 `0,8,4,12,2,10,6,14,1,9,5,13,3,11,7,15`.
Initial state is MD5's: `0x67452301, 0xefcdab89, 0x98badcfe, 0x10325476`.

**Register budget:** MD4 needs strictly less than MD5 (no per-round constant load, and the majority function `G` needs one extra temp but the missing `I` round frees the trick MD5 needed). Start from the same 5-chain (20-way) shape `md5neon_gen.py` documents; if `G` will not fit in the per-chain budget, drop to 4 chains and **say so in the report with the measured cost** rather than silently changing `neonChains`, which is shared with MD5.

**THE ASCII RULE — the single most important requirement in this plan.**

NTLM eligibility must additionally require that **every byte of every charset in every segment is < 0x80**. Reason: `utf16le` (`hash.go:468`) is `utf16.Encode([]rune(s))`, i.e. UTF-8 decode then UTF-16 encode. For ASCII that matches the fast path's `b, 0x00` expansion exactly. For a non-ASCII byte it does not — `[]rune(string([]byte{0xC3}))` is U+FFFD, so the scalar path emits `0xFD 0xFF`. A `?b` mask (full byte range) through a naive fast path would therefore compute **different digests than Hashsmith's own scalar path**, silently.

MD4 proper is `encRaw` and needs no such guard.

func TestNTLMFastPathRejectsNonASCIICharsets(t *testing.T) {
	ascii := bruteLayout("abc", 2, 2)
	if _, ok := fastPathEligible("ntlm", "", ascii); !ok {
		t.Error("ntlm over an ASCII charset should be eligible")
	}
	high := bruteLayout(string([]byte{'a', 0xC3, 0xFF}), 2, 2)
	if _, ok := fastPathEligible("ntlm", "", high); ok {
		t.Error("ntlm over a charset with bytes >= 0x80 must NOT be eligible")
	}
	// md4 takes raw bytes, so the same charset is fine for it.
	if _, ok := fastPathEligible("md4", "", high); !ok {
		t.Error("md4 over a high-byte charset should still be eligible")
	}
}

// Proves the guard is not merely cosmetic: for a high-byte candidate the two
// encodings genuinely differ, which is why eligibility has to exclude them.
func TestUTF16LEDiffersFromNaiveExpansionOnHighBytes(t *testing.T) {
	s := string([]byte{0xC3})
	naive := []byte{0xC3, 0x00}
	if bytes.Equal(utf16le(s), naive) {
		t.Skip("utf16le matches naive expansion here; the ASCII guard may be unnecessary")
	}
	t.Logf("utf16le(%q) = %x, naive = %x — guard is load-bearing", s, utf16le(s), naive)
}

// NTLM's candidate ceiling is 27, not 55, because UTF-16LE doubles the message.
func TestNTLMFastPathLengthCeiling(t *testing.T) {
	if _, ok := fastPathEligible("ntlm", "", bruteLayout("ab", 27, 27)); !ok {
		t.Error("ntlm at length 27 should be eligible")
	}
	if _, ok := fastPathEligible("ntlm", "", bruteLayout("ab", 28, 28)); ok {
		t.Error("ntlm at length 28 must not be eligible (2*28 > 55)")
	}
}
